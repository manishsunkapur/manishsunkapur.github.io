Project 01 · Quality Intelligence · Problem framing

Help frontline teams find the right report during downtime.

Prior discovery captured a need to identify defect type and retrieve the relevant report faster. This is a learning project using reported inputs and fictional prototype data.

User + situation

Operators and newer engineers

Investigating a defect while production is stopped. Confirm whether these are one or two user groups.

Reported friction

Finding and choosing information

Wrong records or parameters, unreliable SOP links, and relevant information split across two systems.

Reported evidence

50 vs 22 minutes

Median investigation time for newer vs experienced engineers, as reported earlier. Source and method need verification; downtime cost is unknown.

Problem statement · user / need / outcome

Make the correct next step easier to find.

During downtime, help the investigator identify the defect and verify the relevant approved report and parameter, so investigation can continue without guesswork or reduced accuracy.

JTBD

“When downtime occurs and I have a clue, help me find and verify the right record and parameter so I can continue the investigation faster without guessing.”

SMART pilot objective · draft, not a committed target

Reduce time to the correct confirmed record while preserving the stated accuracy guardrail.

Make this measurable only after baseline, cohort, accuracy definition, pilot target and test window are agreed.

Solution concept · current prototype

A guided flow that keeps the user in control.

Current demo stages. Additional validation and supervisor steps are planned for the next iteration, pending build and verification.

Search

Compare

Review candidates by source and details.

Review

Select a record and parameter before confirming.

Guidance

Open the next approved step after confirmation.

Exception paths

Make uncertainty actionable

Exact or contextual match, ambiguous results, no results, wrong parameter, and unavailable source each need a clear next action. A failed source must not look like a complete search.

Planned · verify after next build

Report validation + supervisor support

Check source, revision, status, freshness, applicability and completeness; then offer a documented supervisor review when evidence is insufficient. Keep decisions human-owned and auditable.

Prototype finding: fictional NC-2048 returned four candidates without visible match reasons. Add evidence for each match and distinguish exact from contextual results. NC-2048 is sample data, not a customer record.
Measurement framework · KPI + guardrails

Improve speed without rewarding unsafe shortcuts.

Prototype task timing and real downtime outcomes must be reported separately.

Primary KPI

Time to correct information

Median time from a standard clue to confirmation of the correct approved record and parameter.

Quality guardrail

Accuracy ≥ 96%*

User-stated threshold. Confirm definition, denominator, source and adjudicated test set with a quality SME.

Diagnostic signals

Completion + escalation

Correct confirmations / eligible starts; drop-off by step; supervisor escalations, separating avoidable from necessary.

Measurement rule: do not suppress a required quality/safety escalation to improve a metric. Define eligible starts and start/stop timestamps before comparing results.
